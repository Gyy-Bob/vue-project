## 4. 接口封装（严格按业务文档实现）

### 4.1 统一响应约定

HTTP 状态码一律 200，业务结果看 `code`：`code === 0` 成功；非 0 为业务错误，前端以 `message` 提示。

```js
// api/request.js
import axios from 'axios'
import { ElMessage } from 'vue'          // 或自研 toast 组件
import router from '@/router'

const request = axios.create({ baseURL: '/api/v1', timeout: 10000 })

// 请求拦截：自动携带 JWT
request.interceptors.request.use((config) => {
  const userStore = useUserStore()
  if (userStore.token) config.headers.Authorization = `Bearer ${userStore.token}`
  return config
})

// 响应拦截：code !== 0 统一转错误
request.interceptors.response.use(
  (res) => {
    const { code, message, data } = res.data
    if (code === 0) return data
    if (code === 40100) {                 // 凭证无效/过期
      useUserStore().logout()
      router.push('/login')
    }
    return Promise.reject({ code, message })
  },
  (err) => Promise.reject({ code: -1, message: '网络异常，请稍后重试' })
)
```

### 4.2 三个 API

```js
// api/auth.js
export const register = (data) => request.post('/auth/register', data)
// data: { userName, password, userAge?, userNote? }

export const login = (data) => request.post('/auth/login', data)
// data: { userName, password }  →  { token, expiresIn, userId, userName }

export const getReportUsers = (params) => request.get('/report/users', { params })
// params: { pageNum?, pageSize?, userName?, startDate?, endDate? }
```

## 5. 页面流程

### 5.1 登录页（对应设计稿第 1 页）

- 左侧品牌区：Logo「AURORA · 云启科技」+ 标语「智启未来 / 高效管理每一刻」。
- 右侧表单：标题「欢迎回来」，账号输入框（placeholder：请输入账号或邮箱）、密码框（带可见性切换 👁）、「记住我」勾选、「登录」金色按钮、底部「还没有账号？立即注册」链接。

**交互流程：**

```
点击登录
  ├─ 前端校验：userName 非空且 2–50 字符；password 非空且 8–32 位
  │     └─ 不通过 → 输入框下方红字提示，不发请求
  ├─ POST /api/v1/auth/login { userName, password }
  ├─ code = 0（登录成功）
  │     ├─ Pinia + localStorage 保存 token / userId / userName / expiresIn
  │     ├─ Message 成功提示「欢迎回来，{userName}」
  │     └─ 路由跳转 /menu
  └─ code ≠ 0（登录失败）→ 表单顶部红色错误条，展示后端 message
        ├─ 40101 用户名或密码错误
        ├─ 40302 账号已被禁用，请联系管理员
        ├─ 40001 缺少必填参数
        └─ 50000 服务内部错误 / 网络异常
```

> 「记住我」勾选时 token 存 `localStorage`，不勾选存 `sessionStorage`（一期简单实现：统一 localStorage）。
> 设计稿中的「忘记密码」「其他登录方式（微信/手机/邮箱）」为装饰元素，一期不做功能，仅保留样式或隐藏。

### 5.2 注册页（对应设计稿第 2 页）

- 入口：登录页底部「立即注册」→ 跳转 `/register`。
- 表单：标题「创建账户」，用户名、密码（带可见性切换）、确认密码、备注（可选，对应接口 userNote，≤500 字）、「注册」按钮、底部「已有账户？返回登录」。
- 设计稿含「邮箱」与「服务条款勾选」：接口无邮箱字段 → **邮箱输入框不做**；条款勾选改为前端必勾交互（不提交到后端）。

**交互流程：**

```
点击注册
  ├─ 前端校验（全部通过才发请求）
  │     ├─ userName：2–50 字符，仅中文/字母/数字/下划线（正则 ^[\u4e00-\u9fa5A-Za-z0-9_]{2,50}$）
  │     ├─ password：8–32 位，须同时含字母和数字（正则 ^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d!@#$%^&*_.+-]{8,32}$）
  │     ├─ 两次密码一致
  │     └─ userAge（若展示）：0–150 整数；userNote ≤ 500 字
  ├─ POST /api/v1/auth/register { userName, password, userAge?, userNote? }
  ├─ code = 0（注册成功）
  │     ├─ Message 成功提示「注册成功，请登录」（展示新 userId 更佳）
  │     └─ 跳回 /login，并把注册成功的 userName 预填进登录表单
  └─ code ≠ 0 → 表单顶部红色错误条
        ├─ 40901 用户名已被注册 → 用户名输入框标红聚焦
        ├─ 40002 参数格式错误（含用户名非法字符 / 密码复杂度不足 / 年龄越界）
        ├─ 40001 缺少必填参数
        └─ 50000 服务内部错误
```

### 5.3 菜单页（改造自设计稿第 3 页，仅保留一个功能）

- 布局：左侧深色侧边栏（AURORA Logo + 「工作台」导航项 + 底部当前登录人头像/账号），顶部欢迎条（「下午好，{userName}」+ 登出按钮）。
- **唯一功能：查询所有注册人员信息**（业务 3）。
  - 顶部统计卡片：注册总人数 `summary.total`、今日新增 `summary.todayCount`、禁用账号 `summary.disabledCount`。
  - 搜索栏：用户名模糊搜索 `userName`、注册时间范围 `startDate / endDate`（yyyy-MM-dd 日期选择器）。
  - 用户表格：用户 ID、账号、年龄（空显示 —）、状态（1 启用=绿色标签 / 0 禁用=红色标签）、注册时间。
  - 分页条：pageNum / pageSize / total / pages，pageSize 默认 10（可选 10/20/50，上限 100）。

**交互流程：**

```
进入 /menu（守卫已确认有 token）
  └─ onMounted 自动加载：GET /api/v1/report/users?pageNum=1&pageSize=10
点击查询 / 翻页 / 改 pageSize
  └─ 携带当前筛选条件重新请求（Authorization: Bearer <token> 由拦截器注入）
响应 code = 0
  ├─ summary 渲染三张统计卡
  └─ list 渲染表格 + 分页元信息
响应 code ≠ 0
  ├─ 40100 未登录或凭证无效 → 清 token，跳 /login，提示「登录已过期，请重新登录」
  ├─ 40002 日期格式错误 / 40003 pageSize 越界 → 提示后端 message
  └─ 50000 / 网络异常 → 表格空态 + 重试按钮
点击「退出登录」
  └─ 清空 Pinia 与 localStorage → 跳 /login
```

## 6. 全局错误处理约定

| 层级 | 处理方式 |
| --- | --- |
| 表单校验 | 输入框下方行内红字，不发请求 |
| 业务错误（code≠0） | 页面内错误条 / Message 弹提示，文案**直接使用后端 message** |
| 40100 | 任意页面触发 → 清凭证 → 统一跳登录页 |
| 网络/超时 | 统一「网络异常，请稍后重试」 |

## 7. 状态管理设计（Pinia user store）

```js
state:  { token, userId, userName, expiresIn }
actions:
  setLogin(data)    // 登录成功写入 + localStorage 持久化
  logout()          // 清空 state + localStorage，路由回 /login
getters:
  isLogin           // !!token
```

## 8. 端到端流程总览

```
 [登录页] ──点击"立即注册"──> [注册页]
    │                            │ 注册成功（code=0）
    │ <──────跳回登录页（预填用户名）──────┘
    │ 输入账号密码 → POST /auth/login
    ├─ 失败(40101/40302) → 页面显示错误信息，停留登录页
    └─ 成功(code=0) → 存 token → 跳转 [菜单页]
                                     │ GET /report/users（带 JWT）
                                     ├─ 40100 → 踢回登录页
                                     └─ code=0 → 渲染统计卡 + 用户表格 + 分页
```
